The dedicated pool has one connection and closes after every result. A PostgreSQL advisory lock prevents concurrent runs of this utility against the same database. Each SQL statement is bounded by 15 seconds, lock waits by 3 seconds, and the database operation by 60 seconds; the CLI has a 70-second last-resort process limit. Interruption destroys its connection. PostgreSQL rolls back an open transaction when it processes the disconnect; socket closure is not instant query cancellation, so the server statement timeout also matters. A disconnect during commit can leave an uncertain result and requires inspection before retrying. Drizzle creates its ledger scaffolding before the application-migration transaction, so a failed run can leave an empty ledger table. Migration SQL/journal hashes are pinned and the existing ledger must be an exact reviewed prefix; malformed, changed, extra, or future migration history fails closed. These checks do not attest to an otherwise compromised database or detect every out-of-band schema change.
